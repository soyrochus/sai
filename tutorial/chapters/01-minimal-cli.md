# Chapter 1 — A program that understands arguments

## Product goal

Build a Rust program that accepts one natural-language request and prints it exactly. Nothing calls a model or executes a command yet.

## Rust concepts

- A Cargo package and binary target.
- `main` as the process entry point.
- Structs generated by a derive macro.
- Owned `String` values.
- Basic unit tests.

## Before you build

The smallest useful contract is:

```text
INPUT:  sai-course "list Rust files"
OUTPUT: Request: list Rust files
```

The quotation marks belong to the shell. Rust receives one argument containing spaces.

Add Clap:

```bash
cargo add clap --features derive
```

## AI collaboration script

```text
I have a new Rust binary project. Plan the smallest change that accepts exactly one required positional String with clap and prints it unchanged. Explain what the derive macro generates. Do not add subcommands, configuration, async code, or an AI API.
```

Reject a proposal that introduces abstractions for future chapters. Today there is only one input and one output.

## Build

Replace `src/main.rs`:

```rust
use clap::Parser;

#[derive(Debug, Parser)]
#[command(name = "sai-course")]
struct Cli {
    /// Describe the command you want.
    request: String,
}

fn render_request(request: &str) -> String {
    format!("Request: {request}")
}

fn main() {
    let cli = Cli::parse();
    println!("{}", render_request(&cli.request));
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn request_is_preserved() {
        assert_eq!(render_request("list Rust files"), "Request: list Rust files");
    }
}
```

Run it:

```bash
cargo run -- "list Rust files"
```

`cli.request` owns its text. `render_request` only needs to inspect it, so the function borrows `&str`. Passing `&cli.request` creates a temporary shared borrow without copying the string.

## Compiler conversation

Try this deliberately incorrect signature:

```rust
fn render_request(request: String) -> String
```

It compiles if called once, but calling it twice moves the `String` the first time:

```rust,compile_fail
println!("{}", render_request(cli.request));
println!("{}", render_request(cli.request));
```

The diagnostic says the value was used after move. The formatter does not need ownership, so borrowing is the better API. This is the first recurring Rust question: **does this function need to own, mutate, or only observe the value?**

## Tests

Add a CLI-shape test:

```rust
#[test]
fn cli_accepts_a_multiword_request_as_one_argument() {
    let cli = Cli::try_parse_from(["sai-course", "list Rust files"]).unwrap();
    assert_eq!(cli.request, "list Rust files");
}
```

Run:

```bash
cargo test
cargo run -- "list Rust files"
cargo run -- --help
```

The happy path is automated. The help output is a brief manual check because its exact formatting belongs to Clap and may change between versions.

## Review checklist

- Is there exactly one positional argument?
- Is the request preserved rather than split inside Rust?
- Does `render_request` borrow because it only reads?
- Can you explain why `String` is needed in `Cli` but `&str` is enough in the formatter?
- Did AI add anything not required by the contract?
